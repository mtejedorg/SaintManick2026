Tech

How Saint Manick is built. The project is in early development, and this page describes the code as it is today.

Stack

Godot 4.6.3 (Forward+), GDScript only. It is a 3D project: characters are CharacterBody3D, hit areas are Area3D, and the 2.5D look comes from a 3D world filmed by a constrained camera. The audio files are placeholder tones. AudioManager loads clips by name, and some sound effects are not wired up yet.

Architecture

Six game autoloads, plus a debug-only capture helper (F12 saves a screenshot; it does nothing in release builds):

AutoloadRole
SignalBusGlobal events only (health to HUD, enemy died, beat). Parent-child talk inside a scene uses plain node signals.
ConductorThe tempo engine. It runs its own clock, emits beat, downbeat and tempo_changed, and supports variable BPM and several meter layers.
SaveManagerThe only code that touches user://. It saves meta-progression, never volatile run state, and writes atomically with a backup.
GameManagerRun state, currencies, checkpoints, the death beat and the demo-mode flag.
HitStopHit-stop graded by the damage of the landed hit.
AudioManagerLoads clips by name, and does nothing on a missing file by design.

Nick, the enemies and the camera each run on a node-based hierarchical state machine, so a new behaviour is a new state node, not another branch in an if ladder. The camera's machine (Sidescroll, Transitioning, TopDown) owns the swap between plane-locked and free movement. Every tuning number lives in a Resource (.tres): enemy stats, combo definitions, shop upgrades, run boosters and the player's tuning. Projectiles for the bullet-hell phase come from an object pool and are never freed mid-combat.

Diagram, drawn from the architecture document.

A hit is a DamageInfo carrying amount, knockback, stun, shield-breaker, source and invulnerability flags, never a raw integer. The HealthComponent owns the one death rule: shield, then HP, then a life, then permadeath at 0 HP with 0 lives. Hazards, falls and boss attacks go through the same path. Respawn is deferred out of the physics callback, because changing physics state during a flush caused real bugs.

Tests and verification

The suite has 610 tests in 77 files, all passing on 2026-10-28. It runs headless with the project's own framework, and the runner swaps in a temporary save file, so a test never touches a real profile. Every change also gets an import pass, a 300-frame smoke run of the title screen and of the slice, and a log search for script, shader and loader errors. The tests cannot see those errors. A capture tool renders every zone, the HUD and the menus through the real drone camera for visual review. The Windows export has its own gate: the exported build is smoke-tested as well.

Built solo with AI coding agents

Saint Manick is built solo with AI coding agents (Claude Code). The repository configures sixteen specialist agents in .claude/agents/, and a routing table in CLAUDE.md sends each kind of request to one of them:

code-architect (triage, docs, housekeeping) · senior-dev (multi-file implementation) · ui-designer · ux-designer · tester · qa-reviewer · mechanics-designer · level-designer · artist-2d · artist-3d · vfx-artist · render-pipeline · shader-artist · audio-designer · narrative-designer · librarian (knowledge lookups)

Two implementer agents, developer-sonnet and developer-haiku, write the code from briefs. They live in the author's own agent folder, outside the repository. One house rule: an agent's “done” report is checked against the logs before anything is built on it.
